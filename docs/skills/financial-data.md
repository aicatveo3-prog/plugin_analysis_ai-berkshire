# `/financial-data` · 재무 데이터 교차 검증 규칙

> 📄 원문: [skills/financial-data.md](https://github.com/xbtlin/ai-berkshire/blob/main/skills/financial-data.md) · 원문은 중국어이며, 아래는 한국어 번역입니다.

::: tip 한눈에 보기
- **무엇을 하나요?** 기업 재무 데이터를 어디서, 어떤 순서로 가져오고 어떻게 검증할지 정한 규칙집이에요. 핵심 숫자는 반드시 서로 다른 두 출처에서 가져와 비교하고, 1%가 넘게 차이 나면 표시하게 해요.
- **언제 쓰나요?** 기업 재무 데이터가 들어가는 모든 리서치에서 써요. 다른 분석 스킬들이 데이터를 모을 때 기본 규범으로 따르는 문서예요.

- **결과물:** 별도 보고서 파일을 만들기보다, 각 핵심 수치에 두 출처의 값·오차율·✅/⚠️/❌ 표시를 붙인 형식으로 데이터를 정리해 줘요.
- **핵심 특징:** 시장별 1순위·2순위·1차 원문 출처 지정, 오차 구간별 처리 규칙, GAAP/환율/회계연도 등 흔한 차이 원인 정리, 수정주가를 섞어 쓰지 않는 규칙이 특징이에요.
:::

## 번역 전문

**원제:** 재무 데이터 수집과 교차 검증 규범

이 규범은 기업 재무 데이터가 관련된 모든 리서치에 적용됩니다. **모든 핵심 데이터는 두 개의 독립된 출처에서 가져와야 하며, 오차가 1%를 넘으면 반드시 표시해야 합니다.**

## 데이터 출처 우선순위

### 미국 주식(PDD, 텐센트 ADR, 넷이즈 ADR 등)

| 우선순위 | 출처 | URL | 수집 방법 |
|--------|------|-----|---------|
| 1(주) | **macrotrends** | macrotrends.net/stocks/charts/{ticker} | 바로 접속, 가입 불필요 |
| 2(보조) | **stockanalysis** | stockanalysis.com/stocks/{ticker}/financials | 바로 접속, 가입 불필요 |
| 1차 원문 | SEC EDGAR | sec.gov/cgi-bin/browse-edgar | 10-K / 10-Q 원문 |

### 홍콩 주식(텐센트 0700, 넷이즈 9999, 메이퇀 3690 등)

| 우선순위 | 출처 | URL | 수집 방법 |
|--------|------|-----|---------|
| 1(주) | **aastocks** | aastocks.com/tc/stocks/analysis/company-fundamental | 바로 접속 |
| 2(보조) | **macrotrends**(ADR 코드) | 텐센트는 TCEHY, 넷이즈는 NTES 사용 | 바로 접속 |
| 1차 원문 | HKEX 공시 사이트(HKEXnews) | hkexnews.hk | 연차보고서 PDF |

### A주(37 인터랙티브 엔터테인먼트, G-bits 등)

| 우선순위 | 출처 | URL | 수집 방법 |
|--------|------|-----|---------|
| 1(주) | **둥팡차이푸(Eastmoney)** | eastmoney.com → 종목 코드 검색 → 재무제표 | 바로 접속 |
| 2(보조) | **쥐차오쯔쉰(cninfo)** | cninfo.com.cn | 연차·분기 보고서 원본 PDF |

### 대만 주식(TSMC 2330, 미디어텍 2454, 라간정밀 3008 등)

| 우선순위 | 출처 | URL | 수집 방법 |
|--------|------|-----|---------|
| 1(주) | **FinMind API** | api.finmindtrade.com | `tools/twstock_data.py`(의존성 없는 스크립트, 아래 참조) |
| 2(보조) | **Goodinfo 대만 주식 정보망** | goodinfo.tw/tw/StockDetail.asp?STOCK_ID={코드} | 바로 접속 |
| 1차 원문 | 공개정보관측소(MOPS) | mops.twse.com.tw | 재무제표 원문/월 매출 공시 |

**FinMind 데이터 수집 도구**(대만 주식 분석 시 우선 호출하며, 출력에 시가총액 검산이 포함됨):

```bash
python3 tools/twstock_data.py quote 2330        # 최신 시세 + PER/PBR/배당수익률 + 시가총액 검산
python3 tools/twstock_data.py valuation 2330    # 밸류에이션 지표 + 1년 PER 구간 + 52주 최고/최저
python3 tools/twstock_data.py financials 2330   # 최근 5년 연간 핵심 재무(매출/매출총이익률/지배주주 순이익/EPS/ROE)
python3 tools/twstock_data.py revenue 2330      # 최근 13개월 월 매출과 전년 동월 대비
python3 tools/twstock_data.py dividend 2330     # 최근 연도 배당 정책(현금/주식 배당, 배당락일)
python3 tools/twstock_data.py search 台積        # 종목 코드 검색(대만 주식 종목명은 번체자임에 유의)
```

대만 주식 특별 유의 사항:

1. **통화 단위는 대만달러(TWD)입니다.** 홍콩달러/위안화/달러와 섞어 표기할 때는 반드시 명시해야 하며, 시장 간 비교 시에는 먼저 한 통화로 환산합니다
2. **월 매출은 대만 주식만의 강점입니다**: 상장·장외 상장사는 매월 10일 전까지 전월 매출을 의무 공시하며, 이는 펀더멘털 변곡점을 추적하는 가장 빠른 공개 신호입니다. earnings-review/thesis-tracker 유형의 분석에서는 이를 우선 활용해야 합니다(`revenue` 하위 명령)
3. FinMind 손익계산서는 **분기 단일 값**이며, 도구가 자동으로 연간 값으로 합산합니다. 4개 분기가 채워지지 않은 연도에는 "앞 N개 분기 누계만"이라고 표시됩니다
4. FinMind는 가입하지 않아도 바로 쓸 수 있습니다(시간 단위 호출 한도 있음). 가입 후 받은 API token은 **로컬에만 저장하고 git에 커밋하는 것을 엄금합니다.** 도구는 우선순위에 따라 자동으로 읽습니다: ① 환경 변수 `FINMIND_TOKEN`; ② 로컬 파일 `local/finmind_token.txt`(`local/`은 `.gitignore`로 영구 제외되어 있으므로, token을 이 파일에 한 줄로 적어 두면 됩니다). token은 보고서, skill, commit에 나타나서는 안 됩니다
5. 교차 검증: FinMind 수치를 Goodinfo(또는 macrotrends의 ADR, 예: TSM)와 대조하며, 오차 규칙은 아래와 같습니다. TSMC처럼 ADR이 있는 회사는 ADR과 대만 원주 사이의 환율/예탁 비율 차이에 유의합니다(1 TSM ADR = 2330 5주)

## 실행 규범

### 1단계: 데이터 수집

각 재무 지표(매출, 순이익, 매출총이익률, 영업현금흐름, 부채비율 등)마다 **출처 1**과 **출처 2**에서 각각 값을 가져옵니다.

### 2단계: 오차 계산과 표시

```
오차율 = |출처1 수치 - 출처2 수치| / 출처1 수치 × 100%
```

| 오차 | 처리 방법 |
|------|---------|
| ≤ 1% | ✅ 일치. 출처 1의 수치를 쓰고 두 출처를 모두 표기 |
| 1% ~ 5% | ⚠️ "데이터 차이 있음"으로 표시하고, 두 수치를 모두 적고 가능한 원인(환율/회계 기준)을 설명 |
| > 5% | ❌ "데이터에 중대한 차이 있음"으로 표시하고, 반드시 원본 실적 보고서를 확인해야 하며 그대로 사용해서는 안 됨 |

### 3단계: 데이터 표기 형식

모든 핵심 데이터는 다음 형식으로 표기해야 합니다:

```
매출: 1,239억 위안 ✅
  - macrotrends: 1,241억 위안
  - stockanalysis: 1,237억 위안
  - 오차: 0.3%
```

차이가 있는 경우의 예:
```
순이익: 245억 위안 ⚠️ 데이터 차이 있음
  - macrotrends: 245억 위안(GAAP)
  - stockanalysis: 278억 위안(Non-GAAP)
  - 오차: 13.5% — 원인: 회계 기준 차이(GAAP vs Non-GAAP)
```

## 흔한 차이 원인(반드시 데이터 오류인 것은 아님)

| 원인 | 설명 |
|------|------|
| GAAP vs Non-GAAP | 가장 흔하며, 특히 이익 관련 데이터에서 많음 |
| 환율 환산 | 홍콩달러/위안화/달러 환산 시점이 다름 |
| 회계연도 정의 | 역년 vs 회계연도(예: 애플의 회계연도는 10월에 끝남) |
| 연결 기준 | 비지배지분 포함 여부 |
| 데이터 업데이트 지연 | 어떤 플랫폼이 아직 최신 분기 실적을 반영하지 않음 |

## 특별 규칙

1. **비상장 회사**(미호요, 릴리스 게임즈 등): 1차 데이터 출처가 하나뿐일 때는 데이터 앞에 `[추정]`을 표시하고, 교차 검증은 하지 않습니다
2. **분기 데이터 vs 연간 데이터**: 교차 검증은 연간 데이터를 우선 사용합니다. 분기 데이터는 일부 출처에서 반영이 늦을 수 있습니다
3. **원본 실적 보고서 우선**: 두 출처가 모두 원본 실적 보고서(10-K/연차보고서 PDF)와 맞지 않으면 원본 실적 보고서를 기준으로 하고, 출처 오류로 표시합니다

## 주가와 수정주가(과거 시계열 분석 시 필독)

가격에는 세 가지 기준이 있으며, 섞어 쓰면 과거 주가 위치, 장기 상승률, 과거 밸류에이션 분위가 모두 왜곡됩니다:

| 기준 | 의미 | 용도 |
|------|------|------|
| 미수정 | 실제 체결가. 권리락·배당락일에 갭이 생김 | '현재 시점' 스냅샷에만 사용 |
| 전방 수정 | 최신 가격을 기준으로 과거 가격을 조정 | 과거 주가 비교, N년 상승률, 과거 PER 밴드에는 모두 이것을 사용 |
| 후방 수정 | 상장 첫날을 기준으로 이후 가격을 조정 | 과거 총수익률/연환산 수익률 계산 |

(역주: '전방 수정'은 국내에서 흔히 쓰는 수정주가와 같은 방식으로, 현재가는 그대로 두고 과거 가격을 낮춰 맞춥니다. '후방 수정'은 상장 당시 가격을 그대로 두고 이후 가격을 누적 조정합니다.)

규칙:

1. 과거 가격이 관련된 분석은 **전방 수정**으로 통일하며, 한 분석 안에서 수정 출처와 미수정 출처를 **섞어 쓰면 안 됩니다**.
2. 현재 시가총액/현재 PER은 **현재 실제 주가 × 현재 총 발행주식 수**로 계산하면 되며, 수정주가와는 무관합니다 — 수정주가는 과거 시계열에만 영향을 줍니다.
3. 주식 분할/대규모 무상증자·주식배당을 거친 주당 지표(과거 EPS, 과거 주가)는 반드시 수정해 되돌린 뒤 전년 대비 비교해야 합니다.
4. 총수익률/연환산 수익률에는 배당을 포함해야 합니다(후방 수정에는 이미 포함됨). 가격 상승률만 보면 과소평가됩니다.
5. 유상증자/자사주 매입 후 시가총액 검산은 최신 총 발행주식 수를 기준으로 합니다(`financial_rigor.py verify-market-cap`은 편차가 5%를 넘으면 확인하라고 알려 줍니다).
