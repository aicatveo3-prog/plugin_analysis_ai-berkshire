# `/investment-team` · 멀티 에이전트 리서치 팀

> 📄 원문: [skills/investment-team.md](https://github.com/xbtlin/ai-berkshire/blob/main/skills/investment-team.md) · 원문은 중국어이며, 아래는 한국어 번역입니다.

::: tip 한눈에 보기
- **무엇을 하나요?** 사업 모델·재무와 밸류에이션·산업 경쟁·리스크와 경영진을 각각 맡은 4개 에이전트를 동시에 돌리고, 팀 리더가 결과를 모아 하나의 투자 보고서로 정리해요.
- **언제 쓰나요?** 한 기업을 여러 각도에서 제대로 깊이 파고들어 매수·관망·회피 판단과 가격대까지 받아 보고 싶을 때 써요.
- **사용 예:** `/investment-team 메이퇀` (원문의 팀 이름 예시: `meituan-research`)
- **결과물:** `~/{회사명}投资研究报告_{날짜}.md`에 네 관점 점수표, 강세·약세 논리, 버핏식 매수 전 체크리스트, 최종 투자 제안이 담긴 보고서가 만들어져요.
- **핵심 특징:** 네 대가 관점의 병렬 분석, 정보 풍부도 등급에 따른 편향 보정, 계산은 반드시 도구로 검증, 게시 전 15% 표본 검수를 거치는 점이 특징이에요.
:::

## 번역 전문

**원제:** 투자 리서치 팀: 4개 역할 병렬 분석 프레임워크

$ARGUMENTS 에 대해 팀 단위 투자 리서치 분석을 수행합니다. Team 도구를 사용해 실제로 여러 에이전트가 병렬로 연구하는 팀을 만듭니다.

## 실행 절차

### 첫 번째 작업: 팀 프레임워크 제시

다음 팀 구조를 사용자에게 보여 주고, 확인을 받은 뒤 시작합니다.

| 역할 | 책임 | 분석 프레임워크 |
|------|------|----------|
| **team-lead**(당신 자신) | 전체 조율, 종합 판단, 최종 보고서 출력 | 네 대가 종합 프레임워크 |
| **business-analyst** | 사업 모델 & 해자 분석 | 돤융핑 관점 |
| **financial-analyst** | 재무제표 & 밸류에이션 분석 | 버핏 관점 |
| **industry-researcher** | 산업 구도 & 경쟁 상황 | 멍거 관점 |
| **risk-assessor** | 리스크 평가 & 경영진 판단 | 리루 관점 |

### 첫 번째 작업 ½: AI 리서치 편향 평가

팀을 만들기 전에, 먼저 해당 회사의 'AI 연구 가능성' 평가를 사용자에게 보여 줍니다.

**정보 풍부도 등급**(연구 전략을 결정함):
| 등급 | 특징 | 연구 전략 조정 |
|------|------|------------|
| A등급(정보 풍부) | 상장된 지 오래됨, 증권사 커버리지가 넓음 | 팀의 중점을 **반대 측면 검증**과 **비컨센서스 관점**에 두어, 시장과 똑같은 '맞는 말이지만 쓸모없는 말'을 출력하지 않도록 합니다 |
| B등급(정보 보통) | 상장된 지 얼마 안 됨, 커버리지 제한적 | 각 에이전트가 추정한 데이터에는 반드시 신뢰도를 표시하고, team-lead가 취합할 때 '데이터 충분도'를 표시합니다 |
| C등급(정보 희소) | 비인기/신규 상장/신흥 시장 | 팀을 '제1원리 모드'로 전환합니다. 보고서의 완결성을 추구하지 않고, 사업 본질에 관한 몇 가지 핵심 질문에 집중합니다 |

**핵심 주의사항**: 자료가 많다 ≠ 확실성이 높다, 자료가 적다 ≠ 확실성이 낮다. AI가 출력할 수 있는 신뢰도 ≠ 투자의 실제 확실성. 확실성은 사업 모델 자체에서 나오며, 자료의 양에서 나오지 않습니다.

등급 결과를 각 에이전트에 알려 연구 방식에 반영하게 합니다.

### 첫 번째 작업 ¾: WebSearch 권한 사전 점검(핵심 · 에이전트의 조용한 품질 저하 방지)

팀을 만들고 백그라운드 에이전트를 하나라도 실행하기 **전에**, 반드시 WebSearch 권한이 허용되어 있는지 먼저 확인해야 합니다.

**사전 점검이 반드시 필요한 이유**: 이 스킬은 `run_in_background: true`로 4개의 백그라운드 하위 에이전트를 실행하는데, **백그라운드 에이전트는 사용자에게 대화형 권한 확인 창을 띄울 수 없습니다**. `WebSearch`가 `.claude/settings.local.json`의 `permissions.allow` 허용 목록에 없으면 하위 에이전트의 인터넷 검색이 **조용히 차단**되고, 그 결과 에이전트는 학습 지식(지식 기준일이 있음)만으로 답하는 수준으로 품질이 떨어지면서도 프레임워크대로 '겉보기엔 완전하지만 실제로는 인터넷에 연결되지 않은' 가짜 리서치를 출력합니다. 이것이 이 스킬의 가장 위험한 실패 모드입니다(issue #58 참고).

**사전 점검 절차**:
1. Bash로 허용 목록에 WebSearch가 포함되어 있는지 확인합니다.
   ```bash
   grep -l '"WebSearch"' .claude/settings.local.json ~/.claude/settings.local.json 2>/dev/null
   ```
2. 두 곳 모두 해당 항목이 없으면(즉 허용되지 않았으면) → **멈추고, 에이전트를 실행하지 마세요**. 사용자에게 다음과 같이 안내합니다.
   > ⚠️ WebSearch가 권한 허용 목록에 없는 것으로 확인되었습니다. 백그라운드 리서치 에이전트가 인터넷에 연결할 수 없어 학습 지식만으로 답하는 수준으로 품질이 떨어집니다. 먼저 `.claude/settings.local.json`의 `permissions.allow`에 `"WebSearch"`를 추가하거나(또는 `/permissions`를 실행해 체크), 이 명령을 다시 실행하세요.
3. 해당 항목이 있으면 → 정상적으로 계속합니다.

### 두 번째 작업: 팀 생성

TeamCreate를 사용해 팀을 만듭니다.
- team_name: `{회사명}-research`(영문 소문자, 예: `meituan-research`)
- agent_type: `team-lead`

### 세 번째 작업: 4개 작업 생성

TaskCreate를 사용해 다음 4개 작업을 만듭니다(각각 subject, description, activeForm이 모두 있어야 함).

#### 작업 1: 사업 모델 분석
- subject: `{회사명}의 사업 모델, 해자와 사용자 가치 분석`
- description 포함 내용:
  1. 사업 모델의 본질: 핵심 사업의 정의, 매출 구조 분해
  2. 플랫폼/제품의 플라이휠 효과가 어떻게 돌아가는가
  3. 해자 분석: 브랜드/전환 비용/네트워크 효과/규모의 경제/기술 장벽을 하나씩 검증
  4. 사용자/고객 가치: 각 이해관계자에게 어떤 고유한 가치를 창출하는가
  5. 사업 매트릭스와 시너지 효과
  6. 돤융핑의 '좋은 사업' 기준 평가: 차별화, 가격 결정력, 지속 가능한 경쟁 우위
  7. 최신 실적 보고서, 산업 보고서 등 공개 정보를 검색하도록 요구

#### 작업 2: 재무와 밸류에이션 분석
- subject: `{회사명}의 재무 데이터, 수익성과 밸류에이션 분석`
- description 포함 내용:
  1. 최근 3~5년 매출, 순이익, 영업이익 추세
  2. 수익성 지표: ROE, ROA, 매출총이익률, 영업이익률
  3. 현금흐름 분석: 영업현금흐름, 잉여현금흐름(FCF), 자본적 지출
  4. 재무상태표 건전성: 현금 보유액, 부채비율, 유동성
  5. 밸류에이션 분석: PER/PSR/PBR/EV 등을 과거 및 동종 업계와 비교
  6. 안전마진 평가: 내재가치 vs 현재 주가
  7. **금융 엄밀성 검증(반드시 Bash로 도구를 호출할 것, 암산 금지)**:
     - 시가총액 검산: `python3 tools/financial_rigor.py verify-market-cap --price {가격} --shares {주식수} --reported {보고된 시가총액} --currency {통화}`
     - 밸류에이션 검산: `python3 tools/financial_rigor.py verify-valuation --price {가격} --eps {EPS} --bvps {주당순자산}`
     - 핵심 데이터 교차 검증: `python3 tools/financial_rigor.py cross-validate --field {필드} --values '{JSON}' --unit {단위}`
     - 3가지 시나리오 밸류에이션: `python3 tools/financial_rigor.py three-scenario --price {가격} --eps {EPS} --shares {주식수(억 주)} --growth {낙관} {중립} {비관} --pe {낙관PE} {중립PE} {비관PE}`
     - 도구 출력 결과를 검증 기록으로서 보고서에 그대로 삽입

#### 작업 3: 산업과 경쟁 분석
- subject: `{산업} 산업 구도와 {회사명}의 경쟁 상황 분석`
- description 포함 내용:
  1. 산업 규모와 성장: 시장 규모, 성장률, 보급률
  2. 경쟁 구도: 주요 경쟁사의 시장 점유율, 경쟁 전략 비교
  3. 핵심 경쟁자 위협 평가: 주요 경쟁사를 하나씩 분석
  4. 각 세부 분야의 구도
  5. 산업 트렌드: 기술 변화, 정책 영향, 신규 진입자
  6. 산업 체인 분석: 상·중·하류의 가치 배분
  7. 최신 산업 데이터와 경쟁 동향을 검색하도록 요구

#### 작업 4: 리스크와 경영진 평가
- subject: `{회사명}의 투자 리스크와 경영진의 질 평가`
- description 포함 내용:
  1. 경영진 평가: CEO의 능력범위, 정직성, 전략적 안목, 자본 배분 능력, 과거 의사결정의 질
  2. 규제 리스크: 현재 및 잠재적 규제 영향
  3. 경쟁 리스크: 각 경쟁사의 위협 정도 평가
  4. 사업 리스크: 신사업 적자, 확장의 불확실성
  5. 거시 리스크: 경기 사이클, 산업 사이클의 영향
  6. 지배구조: 지분 구조, 특수관계자 거래, 주주환원 정책
  7. 장기적 확실성: 10년 뒤 회사는 어떤 모습일까? 무엇이 이 사업 모델을 뒤엎을 수 있을까?
  8. 최신 규제 동향, 경영진 발언 등을 검색하도록 요구

### 네 번째 작업: 4개 병렬 에이전트 실행

Task 도구를 사용해 4개 에이전트를 동시에 실행합니다(**반드시 같은 메시지 안에서 병렬 호출할 것**).

각 에이전트의 설정:
- `subagent_type`: `general-purpose`
- `run_in_background`: `true`
- `team_name`: 해당 팀 이름
- `name`: 해당 역할명(business-analyst / financial-analyst / industry-researcher / risk-assessor)

각 에이전트의 프롬프트 템플릿:

```
당신은 {회사명} 투자 리서치 팀의 "{역할 한국어명}"이며, {대가 이름}의 투자 관점에서 {회사명}을(를) 분석하는 일을 맡습니다.

작업 #{작업 번호}를 완료하세요: {작업 subject}

구체적 요구사항:
{작업 description의 내용}

**연구 방법**:
- WebSearch를 사용해 최신 공개 정보(실적 보고서, 산업 보고서, 뉴스)를 검색할 것
- **재무 데이터는 반드시 두 개의 독립 출처에서 가져올 것**. `skills/financial-data.md` 규범에 따라 실행(미국 주식: macrotrends+stockanalysis, 홍콩 주식: aastocks+macrotrends, A주: 둥팡차이푸(东方财富)+쥐차오쯔쉰(巨潮资讯), 대만 주식: FinMind `tools/twstock_data.py`+Goodinfo). 두 출처 간 오차가 1%를 넘으면 반드시 표시할 것
- 데이터의 정확성을 확보하고, 핵심 데이터에는 출처를 표시할 것
- 분석은 깊이 있게 하고, 겉핥기에 그치지 말 것
- **인터넷 연결 실패를 위장하지 말 것**: WebSearch가 차단되었거나 사용할 수 없다면, 학습 지식을 인터넷 검색 결과인 것처럼 속이지 말 것. 반드시 보고서 맨 위에 「⚠️ 이 보고서는 인터넷에 연결하지 못했으며, 학습 지식(기준일 X)에 기반하므로 신뢰도가 하향됨」이라고 눈에 띄게 표시하고, team-lead에게 사실대로 알려 연구 중단 여부를 결정하게 할 것

**출력 요구사항**:
- 보고서는 상세하게 작성하고, 핵심 데이터는 Markdown 표로 제시할 것
- 각 분석 차원마다 명확한 결론과 점수가 있어야 함
- 보고서 끝에 해당 차원의 전체 결론이 있어야 함

**완료 후**:
1. TaskUpdate를 사용해 작업 #{작업 번호}를 completed로 표시할 것
2. SendMessage로 전체 분석 보고서를 team-lead에게 보낼 것(type: "message", recipient: "team-lead")
```


### 다섯 번째 작업: 보고서 수신 및 진행 상황 추적

- 사용자에게 진행 상황표(어떤 에이전트가 완료했고 어떤 에이전트가 아직 연구 중인지)를 실시간으로 보여 줍니다
- 보고서를 하나 받을 때마다 진행 상황을 갱신하고, 해당 보고서의 핵심 요점(3~5개)을 보여 줍니다
- 4개 보고서가 모두 도착할 때까지 기다립니다

### 여섯 번째 작업: 팀원 종료

모든 보고서를 받은 뒤 4개 에이전트에 shutdown_request를 보냅니다(SendMessage 사용, type: "shutdown_request").

### 일곱 번째 작업: 최종 보고서 종합

4개 분석 보고서를 종합해 다음 구조의 최종 보고서를 출력합니다.

---

#### 1. 한 문장 결론
> 한 단락(50~100자)으로 투자할 가치가 있는지와 핵심 논리를 요약합니다

#### 2. 네 차원 점수 총괄표
| 차원 | 프레임워크 | 점수(별 1~5개) | 핵심 판단 |
|------|------|------------|----------|

종합 점수: X / 5

#### 3. 핵심 데이터 한눈에 보기
주요 재무·영업 지표 표(최근 2년 비교)

#### 4. 차원별 분석 요약

## 중요 주의사항

1. **4개 에이전트는 반드시 병렬로 실행합니다** — 같은 메시지 안에서 Task 도구를 4번 호출하세요
2. **에이전트는 SendMessage로 보고합니다** — 파일로 협업하는 것이 아니라 메시지로 통신합니다
3. **데이터 정확성** — 에이전트가 WebSearch로 최신 데이터를 검색하고, 핵심 데이터는 교차 검증하도록 요구하세요
4. **결론은 명확해야 합니다** — 매수/관망/회피 제안과 구체적인 가격대를 제시하는 것을 피하지 마세요
5. **모든 분석은 데이터로 뒷받침되어야 합니다** — 데이터 출처를 첨부하세요
6. **인내심을 갖고 기다립니다** — 4개 에이전트의 연구에는 몇 분이 걸리므로, 사용자에게 진행 상황을 실시간으로 알려 주세요
7. **반편향 의식** — team-lead는 취합할 때 반드시 다음을 평가해야 합니다: 각 에이전트의 분석이 자료의 풍부함에 제약을 받았는가? 시장 컨센서스에 지나치게 수렴하지는 않았는가? 최종 보고서에는 '정보 풍부도 등급'과 'AI 리서치 한계 고지'가 포함되어야 합니다
8. **정보가 희소할 때의 정직 원칙** — 추측으로 프레임워크를 채워 확실성을 위장하느니, 차라리 보고서에 빈칸을 남기고 '데이터 부족'이라고 표시하세요
