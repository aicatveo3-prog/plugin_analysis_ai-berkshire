# `/news-pulse` · 주가 급등락 원인 파악

> 📄 원문: [skills/news-pulse.md](https://github.com/xbtlin/ai-berkshire/blob/main/skills/news-pulse.md) · 원문은 중국어이며, 아래는 한국어 번역입니다.

::: tip 한눈에 보기
- **무엇을 하나요?** 주가가 크게 움직였을 때 4개 에이전트가 회사 이벤트·규제·업계·시장 심리를 동시에 뒤져서, 급등락의 진짜 원인이 무엇인지 빠르게 판단해 줘요.
- **언제 쓰나요?** 보유·관심 종목이 하루 ±5%, 일주일 ±10% 정도 움직였거나, 실적 발표 뒤 주가가 튀었거나, 뉴스 헤드라인이 소음인지 진짜 신호인지 헷갈릴 때 써요.
- **사용 예:** `/news-pulse 핀둬둬 3일간 12% 하락` (원문의 급등락 입력 예시: "3일간 12% 하락")
- **결과물:** `reports/{회사명}/{회사명}-news-{YYYYMMDD}.md`에 이벤트 타임라인, 원인 분석표, 성격 판단, 행동 제안이 담긴 급등락 원인 보고서가 만들어져요.
- **핵심 특징:** 10~15분 안에 끝나는 속도 우선 설계, 4개 관점 병렬 정찰, '진짜 원인 불명'도 솔직하게 결론으로 내는 점, 매매 결정은 사용자에게 맡기는 점이 특징이에요.
:::

## 번역 전문

**원제:** 회사 뉴스 펄스: 주가 급등락 신속 원인 분석 팀

$ARGUMENTS 에 대해 최근 뉴스 정찰과 급등락 원인 분석을 수행합니다. **이것은 심층 투자 리서치가 아니라 정보에 대한 신속 대응입니다** — 목표는 10분 안에 "이 회사에 최근 무슨 일이 있었는가? 주가 급등락의 진짜 원인은 무엇인가? 투자 논리를 재검토해야 하는가?"에 답하는 것입니다.

## 적용 상황

- 보유/관심 종목의 주가가 크게 오르거나 크게 떨어졌을 때(일반적인 발동 기준: 하루 ±5%, 일주일 ±10%)
- 실적 발표 후 주가가 급등락해, 시장이 무엇에 반응하고 있는지 빨리 파악하고 싶을 때
- 뉴스 헤드라인을 봤지만 소음인지 진짜 신호인지 확신이 서지 않을 때
- **적용하지 않는 경우**: 완전한 투자 리서치(`/investment-team` 사용), 실적 보고서 정독(`/earnings-review` 사용), 장기 투자 논리 추적(`/thesis-tracker` 사용)

## 실행 절차

### 첫 번째 작업: 파라미터와 상황 확인

다음 정보를 사용자에게 명확히 확인합니다($ARGUMENTS 에 제공되지 않은 경우).

| 파라미터 | 설명 | 기본값 |
|------|------|------|
| **회사명** | 중국어/영어/종목 코드 모두 가능 | 필수 |
| **기간** | 뉴스를 정찰할 소급 일수 | 기본 14일, 실적 시즌에는 7일로 줄일 수 있음 |
| **주가 급등락** | 상승/하락 폭 + 기간, 예: "3일간 12% 하락" | 선택, 있으면 원인 분석의 초점을 맞추는 데 사용 |
| **중점 관점** | 회사 이벤트 / 규제 / 업계 / 심리 | 기본은 네 관점을 균등하게 |

사용자가 회사명만 말했다면 먼저 되물으세요: "최근 며칠간의 뉴스를 볼까요? 설명이 필요한 구체적인 주가 급등락이 있나요?" — **말없이 가정하지 마세요**.

### 두 번째 작업: 정보 입수 가능성 등급 분류

[`investment-team.md`](./investment-team)의 A/B/C 등급을 참고하되, 기준 차원은 다릅니다.

| 등급 | 특징 | 정찰 전략 |
|------|------|---------|
| **A등급(정보 풍부)** | 대형주, 언론 보도가 많음, 실적 시즌 | 핵심은 **소음 제거와 원인 분석** — 정보가 너무 많으면 오히려 진짜 원인을 찾기 어려우므로, 각 에이전트는 판단력을 갖추고 '반복 전재'된 2차 뉴스를 걸러내야 합니다 |
| **B등급(정보 보통)** | 중소형주, 보도량 보통 | 표준 모드, 각 핵심 이벤트마다 독립 출처 1~2개를 첨부합니다 |
| **C등급(정보 희소)** | 홍콩 소형주, 신규 상장, 비인기 종목 | '기초 파악 모드'로 전환 — 급등락을 설명할 뉴스를 전혀 찾지 못할 수도 있으며, **그 결론 자체에 가치가 있습니다**(기본적 요인이 아니라 기술적/수급 요인일 수 있음) |

등급을 각 에이전트에 알려 정찰 방식에 반영하게 합니다.

### 세 번째 작업: 팀 생성

TeamCreate를 사용해 팀을 만듭니다.
- `team_name`: `{회사명}-newspulse`(영문 소문자, 예: `pdd-newspulse`)
- `agent_type`: `team-lead`

### 네 번째 작업: 4개의 정찰 작업 생성

TaskCreate를 사용해 다음 4개 작업을 만듭니다.

#### 작업 1: 회사 이벤트 정찰(company-event-scout)

- **subject**: `{회사명}의 최근 {N}일간 회사 자체 이벤트 정찰`
- **description**:
  1. **공식 공시**: 홍콩거래소(HKEX)/SEC/쥐차오(중국 공시 플랫폼) 등 규제 공시 플랫폼의 최근 공시
  2. **실적 보고서와 실적 가이던스**: 최신 분기보고서/연차보고서, 실적 예고, 실적 설명회 요점
  3. **경영진 동향**: 임원 교체, 지분 확대·축소, 자사주 매입, 배당, 주식 보상
  4. **중대 사업 이벤트**: 신제품 출시, 인수합병·구조조정, 사업 분할 매각, 대형 고객/대형 수주
  5. **자본 거래**: 추가 자금 조달, 전환사채, ADR 전환, A주 회귀/상장 폐지 제안
  6. **소송과 컴플라이언스**: 피소, 자진 공시한 컴플라이언스 사건
  7. 각 이벤트에 **날짜 / 출처 링크 / 한 문장 요약 / 주가 급등락과의 연관 가능성(높음/중간/낮음)** 을 표시합니다
  8. 시간 역순의 타임라인 표로 출력합니다

#### 작업 2: 규제와 정책(regulatory-watcher)

- **subject**: `{산업/회사}의 최근 {N}일간 규제와 정책 변화 정찰`
- **description**:
  1. **산업 규제**: 해당 산업의 신규 규정, 벌금, 시정 명령, 인허가 변화
  2. **국경 간 정책**: 미·중 관계(미국 상장 중국 기업), 관세, 수출 통제, 데이터 보안
  3. **세제 정책**: 부가가치세, 법인세, 개인소득세 관련 변화
  4. **반독점과 경쟁법**: 조사, 벌금, 인수합병 불허
  5. **특수 산업 정책**: 의약품 중앙 집중 조달, 교육 '쌍감' 정책(역주: 사교육·숙제 부담 경감 규제), 부동산 '3대 레드라인', 인터넷 플랫폼 규제 등
  6. **통화와 외환**: 해당 회사에 영향을 주는 환율/금리/자본 통제 변화
  7. 각 정책에 **날짜 / 출처 / 해당 회사에 대한 영향 정도(직접/간접/무관)** 를 표시합니다
  8. 중점 판단: '정책 블랙스완'이 막 현실화했는지 여부

#### 작업 3: 업계와 경쟁사(industry-peer-analyst)

- **subject**: `{회사명}의 업계 구도와 경쟁사의 최근 {N}일간 동향 정찰`
- **description**:
  1. **직접 경쟁사**: 핵심 경쟁사 3~5곳을 나열하고, 각각의 최근 이벤트(실적, 제품, 가격 전쟁, 인사)를 조사합니다
  2. **산업 체인 상·하류**: 상류의 원자재/공급업체, 하류의 고객/유통 채널의 최근 가격, 생산 능력, 주문 변화
  3. **산업 전반**: 업황 데이터, 출하량, 수요 측 신호(소비 데이터, 입찰 데이터 등)
  4. **대체재 위협**: 신기술, 새로운 비즈니스 형태가 해당 산업에 주는 충격
  5. **업종 지수 성과**: 같은 업종 종목들의 최근 성과, 해당 회사가 업종 대비 초과/미달/동행했는지
  6. 핵심 판단: **이것이 회사 개별 이벤트인가, 아니면 산업 전체의 베타 변동인가?**
  7. 각 이벤트에 출처와 날짜를 표시합니다

#### 작업 4: 시장 심리와 셀사이드/유명 인플루언서(sentiment-tracker)

- **subject**: `{회사명}의 최근 {N}일간 시장 심리와 기관 관점 변화 정찰`
- **description**:
  1. **셀사이드 등급 변경**: 골드만삭스, 모건스탠리·JP모건, CICC(중국국제금융) 등의 최근 투자의견/목표주가 조정
  2. **기관 보유 변화**: 13F 공시(미국 주식), 홍콩 스톡커넥트(본토→홍콩 투자 경로) 보유 현황, 북향자금(홍콩→중국 본토 투자 자금) 흐름
  3. **공매도 데이터**: 공매도 비율, 새로 발표된 공매도 보고서(있다면)
  4. **유명 인플루언서 관점**: `python3 tools/xueqiu_scraper.py` 를 호출해 돤융핑 등 유명 인플루언서의 최근 관련 발언을 수집할 수 있습니다
     - 돤융핑 user_id: `1247347556`
     - 명령 예시: `python3 tools/xueqiu_scraper.py --user-id 1247347556 --keywords {회사명},{종목코드} --output /tmp/dyp-{회사명}.md`
     - 해당 회사가 돤융핑/리루의 관심 종목일 때만 호출하고, 그렇지 않으면 시간 절약을 위해 건너뜁니다
  5. **루머와 찌라시**: 언론이 확인하지 않은 루머, 소셜 미디어 토론 화제(쉐추(중국 투자 커뮤니티)/X/Reddit)
  6. **기술적 신호**: 주요 지지선/저항선 도달 여부, 대량 블록딜 여부, 신용융자·대주 이상 여부
  7. 핵심 판단: **기본적 요인(펀더멘털) 주도인가, 심리/수급 주도인가?**

### 다섯 번째 작업: 4개 에이전트 병렬 실행

**반드시 같은 메시지 안에서 Task 도구를 4번 병렬 호출하세요**. 각 에이전트 설정:
- `subagent_type`: `general-purpose`
- `run_in_background`: `true`
- `team_name`: `{회사명}-newspulse`
- `name`: 해당 역할명(company-event-scout / regulatory-watcher / industry-peer-analyst / sentiment-tracker)

각 에이전트의 프롬프트 템플릿:

```
당신은 {회사명} 뉴스 펄스 팀의 "{역할 한국어명}"이며, {정찰 차원} 차원의 최근 {N}일간 이벤트 정찰을 담당합니다.

기간: {시작일} ~ {오늘 날짜}
주가 급등락 배경: {사용자가 제공한 급등락 정보, 없으면 "특정 급등락 없음, 정기 점검"이라고 기재}
정보 입수 가능성 등급: {A/B/C}

작업 #{작업 번호}를 완료하세요: {작업 subject}

구체적 정찰 요구사항:
{작업 description의 내용}

**정찰 방법**:
- 시의성 있는 검색은 WebSearch를 우선 사용할 것(키워드에 날짜나 "최근", "latest", "2026" 추가)
- 핵심 이벤트는 WebFetch로 원본 출처(공시 원문, 실적 보고서, 규제 문서)를 정독할 것
- 각 이벤트에 대해 '독립 출처 검증'을 할 것 — 루머는 최소 2개의 독립 출처가 필요함
- **낚시성 제목에 속지 말 것**: 제목과 본문이 일치하지 않는 이벤트는 "제목 오도"라고 표시할 것

**출력 형식(중요)**:
1. **핵심 발견**: 가장 중요한 이벤트 3~5개, 각각 1~2문장
2. **전체 이벤트 타임라인 표**(날짜 역순):
   | 날짜 | 이벤트 | 출처 | 주가 급등락과의 연관성 | 지속성 |
3. **이 차원의 원인 분석 결론**: 정찰한 이벤트를 바탕으로 "이 차원이 주가 급등락을 설명할 수 있는가? 신뢰도는 얼마인가?"에 답할 것
4. **데이터 공백 선언**: 어떤 정보를 찾지 못했는지, 어떤 것에 의문점이 있는지, 어떤 것이 더 많은 정보를 기다려야 하는지
5. '사실'과 '추측'을 엄격히 구분하고, CLAUDE.md의 객관성 원칙을 따를 것

**완료 후**:
1. TaskUpdate를 사용해 작업을 completed로 표시할 것
2. SendMessage로 전체 정찰 보고서를 team-lead에게 보낼 것(type: "message", recipient: "team-lead")
```

### 여섯 번째 작업: 실시간 진행 상황 추적

- 정찰 보고서를 하나 받을 때마다 해당 차원의 핵심 발견 3가지를 사용자에게 보여 줍니다
- 4개 보고서가 모두 도착할 때까지 기다립니다
- 모두 도착하면 SendMessage로 4개 에이전트에 shutdown_request를 보냅니다


### 일곱 번째 작업: team-lead의 종합 원인 분석

4개 정찰 보고서를 취합해 **급등락 원인 분석 보고서**를 출력합니다(리서치 보고서가 아니며, 핵심은 '판단'입니다).

---

#### 1. 한 문장 원인 분석
> 한 단락(30~60자)으로 이번 주가 급등락의 주원인 + 부원인 + 성격 판단(가치 이벤트/심리 변동/불명)을 설명합니다

#### 2. 전체 이벤트 타임라인(4개 차원 통합)

날짜 역순으로 모든 차원의 이벤트를 합칩니다.

| 날짜 | 차원 | 이벤트 | 출처 | 급등락 원인 가중치 |
|------|------|------|------|-----------|
| 2026-04-30 | 회사 | XX | 링크 | 🔴 높음 |
| 2026-04-29 | 업계 | XX | 링크 | 🟡 중간 |
| 2026-04-28 | 심리 | XX | 링크 | ⚪ 낮음 |

가중치 범례: 🔴 높음(단독으로 급등락을 설명하기에 충분) / 🟡 중간(일부 기여) / ⚪ 낮음(배경 소음)

#### 3. 급등락 원인 분석표

| 후보 설명 | 증거 | 반대 증거 | 신뢰도 | 지속성 |
|---------|------|------|------|--------|
| 예: 실적 미스(miss) | 매출이 예상보다 5% 낮음, 매출총이익률 하락 | 일회성 요인에 대해 경영진이 해명함 | 높음 | 단기 1~2주 |
| 예: 업종 베타 | 동종 업체가 같은 기간 8% 하락 | 이 종목의 하락폭이 업종보다 뚜렷이 큼 | 중간 | 업종과 동행 |

#### 4. 성격 판단(핵심 결론)

다음 중 하나에 체크합니다.

- [ ] **가치 이벤트**: 펀더멘털에 실제 변화가 생김(실적, 해자, 경영진, 최종 구도) — 투자 논리 재검토가 필요함
- [ ] **심리/기술적 변동**: 펀더멘털 변화 없음, 수급/심리/베타 주도 — 기회 또는 소음으로 볼 수 있음
- [ ] **진짜 원인 불명**: 주가 급등락 폭에 걸맞은 이벤트를 찾을 수 없음 — **가장 위험한 결론입니다**. 시장이 무언가를 먼저 알고 있거나(내부 정보/선행 매매), 우리가 정보원을 놓쳤을 가능성이 있습니다
- [ ] **혼합**: 일부 가치 이벤트 + 일부 심리 증폭

#### 5. 차원별 정찰 요약

차원별로 가장 중요한 발견 3~5개 + 해당 차원의 원인 기여도를 적습니다.

#### 6. 행동 제안

| 행동 | 권장 여부 | 이유 |
|------|--------|------|
| 투자 논리 재검토 발동(`/thesis-tracker`) | | |
| 실적 보고서 심층 정독 발동(`/earnings-review`) | | |

| 관찰만 함 | | |

#### 7. 향후 7~30일 추적 체크리스트

- [ ] 핵심 관찰 신호 3

#### 8. 정보 공백 선언

이번 정찰에서 풀지 못한 의문점, 찾지 못한 정보, 추가 공시를 기다려야 하는 사항을 솔직하게 나열합니다. **추측으로 채우느니 차라리 '불확실'이라고 표시합니다**.

## 핵심 원칙

1. **속도가 완전함보다 우선합니다** — 이 스킬의 핵심 가치는 10~15분 안에 원인 판단을 내놓는 것이므로, 심층 분석에 빠지지 마세요(그것은 다른 스킬의 역할입니다)
2. **나열보다 원인 판단이 우선입니다** — 이벤트를 찾는 것은 어렵지 않습니다. 어려운 것은 "어떤 이벤트가 이번 주가 급등락에 걸맞은가"를 판단하는 것입니다. 더하기가 아니라 빼기를 하세요
3. **'불명'을 정직하게 마주합니다** — 주원인을 찾지 못하면 "진짜 원인 불명"이라고 명확히 쓰세요. 억지로 인과 사슬을 끼워 맞추는 것보다 가치가 있습니다(시장이 악재를 선반영하고 있을 수 있음)
4. **입장을 미리 정하지 않습니다** — 보유 종목이라는 이유로 "심리 변동일 뿐, 괜찮다" 쪽으로 기울지 마세요. 증거가 가리키는 쪽을 쓰세요
5. **'촉매'와 '우연'을 구분합니다** — 같은 시기에 일어난 이벤트가 반드시 급등락의 주원인은 아닙니다. 영향의 규모가 맞는지 봐야 합니다
6. **정보 입수 가능성을 존중합니다** — C등급 회사는 정말로 아무 뉴스도 찾지 못할 수 있으며, 그 결론 자체를 적어야 합니다
7. **`CLAUDE.md`의 객관성 원칙을 따릅니다** — 모든 판단에 데이터 출처를 붙이고, 사실과 의견을 구분하세요
8. **사용자 대신 결정하지 않습니다** — 원인 분석과 행동 제안 목록은 제시하되, 매매 결정은 사용자가 합니다
