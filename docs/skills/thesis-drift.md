# `/thesis-drift` · 투자 논리 변화 감지

> 📄 원문: [skills/thesis-drift.md](https://github.com/xbtlin/ai-berkshire/blob/main/skills/thesis-drift.md) · 원문은 중국어이며, 아래는 한국어 번역입니다.

::: tip 한눈에 보기
- **무엇을 하나요?** 같은 회사에 대한 예전 보고서와 새 보고서를 나란히 놓고 밸류에이션 기준점·핵심 가정·레드라인·경영진 품질·해자 5개 차원이 각각 Improved / Unchanged / Weakened 중 어디에 해당하는지 판정해요.
- **언제 쓰나요?** 보유 종목의 새 실적이나 큰 사건이 나온 뒤, "내 투자 논리가 정말 바뀐 건지, 주가나 보고서 문장만 바뀐 건지" 가려내고 싶을 때 써요.
- **사용 예:** `/thesis-drift 腾讯` (원문 입력 형식 기준이에요. 비교할 두 보고서 경로를 직접 지정할 수도 있어요.)
- **결과물:** 차원별 변화 표, 증거 차이 내역, 수치 검산, 행동 제안 변화(예: Buy → Hold)를 담은 변화 감지 보고서가 만들어져요. 비교할 과거 기준이 없으면 먼저 `/thesis-tracker`로 기준을 만들라고 안내해요.
- **핵심 특징:** 사실 변화·가격 변화·표현 변화를 구분하고, 판정마다 구체적인 새 증거를 요구하며, 모든 수치는 도구로 검산하고, 레드라인은 따로 우선 처리해요.
:::

## 번역 전문

**원제:** 투자 논리 변화 감지: 사실의 변화와 표현의 변화를 구분하기

$ARGUMENTS 에 대해 투자 논리(thesis) 변화(drift) 감지를 수행합니다.

**지원 입력 형식**:
- `公司名 旧报告路径 新报告路径`(회사명 이전 보고서 경로 새 보고서 경로) — 두 리서치 보고서 또는 논리 스냅샷을 지정해 비교합니다
- `公司名 reports/{회사명}-thesis-旧日期.md reports/{회사명}-thesis-新日期.md` — 날짜가 붙은 두 논리 스냅샷을 비교합니다 (역주: 파일명 끝부분은 각각 이전 날짜와 새 날짜를 뜻합니다)
- `公司名`(회사명) — `reports/{회사명}-thesis.md`와 같은 디렉터리의 과거 스냅샷을 자동으로 찾습니다. 기준(baseline)이 없으면 기준 부재 처리로 넘어갑니다

> "사실이 바뀌면 나는 생각을 바꿉니다. 당신은 어떻게 하십니까?" —— 케인스
>
> "주가 변동은 논리의 변화가 아닙니다. 사실이 바뀌어야 변화입니다." —— AI Berkshire

## 설계 이념

장기 보유에서 가장 어려운 것은 매일 뉴스를 읽는 일이 아니라, 다음 세 가지를 구분하는 일입니다.
- **사실의 변화**: 매출, 이익률, 경쟁 구도, 경영진의 행동, 자본 배분에 검증 가능한 변화가 생김
- **가격의 변화**: 시장 심리나 밸류에이션 배수가 변했지만 사업 자체는 변하지 않음
- **표현의 변화**: 두 보고서의 표현은 다르지만, 밑바탕의 증거와 판단은 변하지 않음

투자 논리 변화 감지의 목표는 **증거가 바뀌었을 때에만 논리의 변화를 인정하는 것**입니다. 보고서의 서술 방식이 바뀌었다고 해서 변화를 만들어 내서는 안 되며, 주가가 오르내린다고 해서 펀더멘털을 잘못 판단해서도 안 됩니다.

이 스킬은 `/thesis-tracker`가 출력하는 구조화된 차원, 즉 핵심 가정 목록, 레드라인 목록, 밸류에이션 기준점, 추적 기록 표에 의존합니다. 이런 구조가 없다면 먼저 기준을 갖춘 뒤 변화 감지를 수행합니다.

## 실행 절차

### 1단계: 작동 모드 판단

`$ARGUMENTS`를 해석합니다.
- 두 보고서 경로가 주어지면 → **지정 보고서 비교** 모드로 진입합니다
- 회사명만 주어지면 → `reports/{회사명}-thesis.md`와 과거 스냅샷을 찾아 **자동 스냅샷 비교** 모드로 진입합니다
- 보고서를 하나만 찾았거나 과거 기준이 없으면 → **기준 부재 처리** 모드로 진입합니다
- 두 보고서가 같은 회사에 관한 것이 아니면 → 중단하고 사용자에게 확인을 요청하며, 회사 간 변화 판단은 하지 않습니다

## 모드 A: 지정 보고서 비교

### A1: 두 보고서 읽기 및 확인

이전 보고서와 새 보고서를 읽어 다음을 추출합니다.
- 보고서 날짜, 회사명, 종목 코드
- 핵심 논리(5문장)
- 핵심 가정 목록
- 레드라인 목록
- 밸류에이션 기준점
- 추적 기록 표
- 경영진 품질 판단
- 경쟁 해자 판단
- 현재 제안 조치(매수 / 보유 / 관망 / 비중 축소 / 전량 매도)

보고서에 핵심 구조가 빠져 있으면 먼저 "구조 누락"을 표시하되, 그래도 본문에서 최대한 증거를 추출합니다. 추출할 수 없는 차원은 "판단 불가"로 표시하며, 결론을 지어내서는 안 됩니다.

### A2: 증거 정규화

두 보고서의 사실 증거를 하나의 표로 정리합니다.

| 차원 | 이전 보고서 증거 | 새 보고서 증거 | 데이터 출처 | 검증 가능 여부 |
|------|-----------|-----------|---------|-----------|
| 밸류에이션 기준점 | | | | |
| 핵심 가정 | | | | |
| 레드라인 | | | | |
| 경영진 품질 | | | | |
| 경쟁 해자 | | | | |

**증거만 비교하고 문체는 비교하지 않습니다.** 두 보고서가 동의어로 바꿔 쓰거나, 순서를 바꾸거나, 어조만 달라졌을 뿐 사실 데이터와 판단 기준치는 변하지 않았다면 Unchanged로 판정합니다.

### A3: 수치와 밸류에이션 검증

모든 수치 변화는 반드시 `tools/financial_rigor.py`로 정확히 계산해야 하며, LLM의 암산은 금지합니다.

```bash
python3 tools/financial_rigor.py verify-valuation \
  --price {현재가격} \
  --eps {EPS} \
  --bvps {주당순자산} \
  --fcf-per-share {주당잉여현금흐름}
```

시가총액, 백분율 변화, 목표가 차이 또는 시나리오별 밸류에이션을 계산해야 한다면 다음을 사용합니다.

```bash
python3 tools/financial_rigor.py verify-market-cap --price {가격} --shares {발행주식수} --reported {보고된시가총액} --currency {통화}
python3 tools/financial_rigor.py cross-validate --field {필드} --values '{JSON}' --unit {단위}
python3 tools/financial_rigor.py three-scenario --price {가격} --eps {EPS} --shares {발행주식수_억주} --growth {낙관} {중립} {비관} --pe {낙관PE} {중립PE} {비관PE}
python3 tools/financial_rigor.py calc --expr '{정확한계산식}'
```

핵심 재무 데이터는 반드시 최소 두 곳의 독립된 출처로 교차 검증해야 합니다. 출처가 부족하거나, 산정 기준이 일치하지 않거나, 재확인할 수 없는 숫자는 반드시 "낮은 신뢰도 / 확인 필요"로 표시해야 합니다.

### A4: 차원별 변화 판정

다음 차원을 고정해서 사용하며, 임의로 늘리거나 줄이지 않습니다.

| 차원 | 판정 중점 | Improved | Unchanged | Weakened |
|------|---------|----------|-----------|----------|
| 밸류에이션 기준점 | 내재가치, PER/PBR/FCF Yield, 안전마진, 목표가 구간 | 안전마진이 커졌거나 내재가치가 상향됐고, 도구로 검산됨 | 밸류에이션 구간과 안전마진에 실질적 변화 없음 | 안전마진이 좁아졌거나, 내재가치가 하향됐거나, 밸류에이션 가정이 무효화됨 |
| 핵심 가정 목록 | 매출 성장률, 이익률, 현금흐름, 사용자/수주/생산능력 등 검증 가능한 가정 | 더 많은 가정이 새 증거로 강화됨 | 가정의 상태와 증거가 대체로 일치 | 가정이 한계적으로 약화, 훼손 또는 붕괴 |
| 레드라인 목록 | 신뢰성, 규제, 사업 쇠퇴, 경쟁사의 돌파, 경영진의 이상 행동 | 기존 레드라인 위험이 해소되거나 크게 낮아짐 | 발동되지 않았고 위험 수준도 그대로 | 레드라인이 발동됐거나 발동 확률이 높아짐 |
| 경영진 품질 | 신뢰성, 자본 배분, 자사주 매입·배당, 실행력, 주주 친화도 | 새로운 행동이 신뢰도를 높임 | 행동이 기존 판단과 일관됨 | 행동이 신뢰를 훼손하거나 자본 배분이 나빠짐 |
| 경쟁 해자 | 시장 점유율, 가격 결정력, 네트워크 효과, 비용 우위, 대체 위협 | 해자가 넓어졌거나 경쟁 우위가 검증됨 | 구도에 실질적 변화 없음 | 해자가 약해졌거나 경쟁사가 돌파함 |

각 차원은 세 가지 결론 중 하나만 낼 수 있습니다: **Improved / Unchanged / Weakened**.

### A5: 증거 기반 규칙

Unchanged가 아닌 모든 결론은 변화를 일으킨 구체적인 새 증거를 인용해야 합니다.
- 실적 보고서 항목: 예) 매출 성장률, 매출총이익률, 영업현금흐름, 자사주 매입 금액, 순현금
- 규제 공시: 예) 10-K/20-F, 연차보고서, 반기보고서, 홍콩거래소 공시, SEC filing
- 뉴스 사건: 예) 경영진 교체, 규제 처벌, 주요 고객 이탈, 경쟁 제품의 돌파
- 가격과 밸류에이션: 이것이 "밸류에이션 변화"인지 "펀더멘털 변화"인지 반드시 밝혀야 하며, 둘을 혼동해서는 안 됩니다

변화를 설명할 증거를 찾을 수 없다면 반드시 **Unchanged** 또는 **판단 불가**로 판정해야 하며, 표현 차이로 변화를 추론해서는 안 됩니다.

### A6: 변화 감지 보고서 출력

#### 보고서 구성

```
1. 비교 대상과 기간
2. 종합 결론: 논리가 변화했는가
3. 차원별 변화 표
4. 증거 차이 내역
5. 밸류에이션과 수치 검산
6. 제안 조치의 변화
7. 불확실한 항목과 보충이 필요한 출처
8. 다음 추적 때 중점 사항
```

#### 차원별 변화 표

| 차원 | 이전 판단 | 새 판단 | 변화 방향 | 근거 증거 | 신뢰도 |
|------|-------|-------|:--------:|---------|:------:|
| 밸류에이션 기준점 | | | Improved / Unchanged / Weakened | | 높음/중간/낮음 |
| 핵심 가정 목록 | | | Improved / Unchanged / Weakened | | 높음/중간/낮음 |
| 레드라인 목록 | | | Improved / Unchanged / Weakened | | 높음/중간/낮음 |
| 경영진 품질 | | | Improved / Unchanged / Weakened | | 높음/중간/낮음 |
| 경쟁 해자 | | | Improved / Unchanged / Weakened | | 높음/중간/낮음 |

**Unchanged 행의 근거 증거 칸에는 `—`를 쓰고, 표를 채우려고 증거를 지어내지 마세요.**

#### 종합 결론은 반드시 다음 질문에 답할 것

1. **논리가 변화했는가?** 변화 없음 / 긍정적 변화 / 부정적 변화 / 증거 부족으로 판단 불가
2. **변화는 어디에서 왔는가?** 밸류에이션 / 펀더멘털 / 경영진 / 경쟁 구도 / 레드라인 사건
3. **사실의 변화인가, 가격의 변화인가?** 명확히 나누어 설명합니다
4. **제안 조치는 어떻게 바뀌는가?** 예) Watch → Buy, Buy → Hold, Hold → Reduce, Reduce → Exit
5. **다음에는 어떤 증거가 필요한가?** 다음 실적 보고서 / 규제 공시 / 경영진 설명 / 경쟁사 데이터

## 모드 B: 자동 스냅샷 비교

### B1: 스냅샷 찾기

`reports/`에서 다음을 찾습니다.
- `reports/{회사명}-thesis.md`
- `reports/{회사명}-thesis-*.md`
- `reports/{회사명}/` 디렉터리 아래에서 파일명에 `thesis`, `论文`, `追踪`(역주: 각각 '논리', '추적'을 뜻하는 중국어 키워드)이 들어간 보고서

시점이 가장 이르고 구조가 온전한 파일을 이전 보고서로, 시점이 가장 최근인 파일을 새 보고서로 선택합니다. 사용자가 날짜를 지정했다면 사용자의 지정을 따릅니다.

### B2: 잘못된 짝짓기 방지

비교하기 전에 반드시 다음을 확인합니다.
- 회사명 또는 종목 코드가 일치함
- 보고서 날짜가 서로 다름
- 두 보고서 모두 추출 가능한 논리 구조나 리서치 결론을 담고 있음

같은 회사임을 확인할 수 없으면 중단하고 사용자에게 명확한 경로를 요청합니다.

### B3: 모드 A 실행

유효한 스냅샷 두 개를 찾으면 모드 A를 빠짐없이 수행합니다.

## 모드 C: 기준 부재 처리

보고서를 하나만 찾았거나 이전 스냅샷을 찾지 못한 경우:

1. 분명하게 밝힙니다: **비교할 과거 기준이 없어 변화 감지를 수행할 수 없습니다**
2. 기억이나 시장에 대한 인상으로 이전 논리를 지어내지 마세요
3. 사용자에게 먼저 `/thesis-tracker {회사명} 建立论文`(논리 수립)을 사용해 구조화된 기준을 만들도록 안내합니다
4. 현재 보고서가 충분히 온전하다면, 이를 `reports/{회사명}-thesis.md`로 저장해 향후 변화 감지의 기준으로 삼도록 제안할 수 있습니다

출력 형식:

```
투자 논리 변화 감지를 수행할 수 없습니다: 과거 기준이 없습니다.
```

## 핵심 원칙

- **표현보다 증거가 우선입니다** — 동의어로 바꿔 쓴 것은 변화가 아니며, 사실 증거가 바뀌어야만 변화입니다
- **주가보다 펀더멘털이 우선입니다** — 주가 등락은 밸류에이션 기준점에만 영향을 줄 뿐, 사업의 질을 자동으로 바꾸지 않습니다
- **수치는 반드시 검산합니다** — 모든 백분율, 밸류에이션 배수, 목표가 차이는 반드시 `tools/financial_rigor.py`로 계산합니다
- **불확실하면 불확실하다고 표시합니다** — 출처가 없거나, 산정 기준이 다르거나, 재확인할 수 없을 때는 억지로 판정하지 마세요
- **레드라인은 따로 처리합니다** — 레드라인 발동은 밸류에이션이 싸다는 점보다 우선하며, 낮은 PER로 가려져서는 안 됩니다
- **출력은 반드시 복기 가능해야 합니다** — 모든 Improved / Weakened 결론은 구체적인 증거까지 거슬러 올라갈 수 있어야 합니다
