# `/deep-company-series` · 8편 장문 기업 시리즈

> 📄 원문: [skills/deep-company-series.md](https://github.com/xbtlin/ai-berkshire/blob/main/skills/deep-company-series.md) · 원문은 중국어이며, 아래는 한국어 번역입니다.

::: tip 한눈에 보기
- **무엇을 하나요?** 한 회사를 《〇〇 이해하기》라는 3~8편짜리 장문 시리즈로 나눠 써요. 인지 리셋 → 해자 → 이익 엔진 → 숨은 자산 → AI 변수 → 재무 → 경영진 → 매수·매도 판단까지 하나의 흐름으로 이어져요.
- **언제 쓰나요?** 증권사 리포트 한 편이 아니라, "90분을 들여 한 회사를 제대로 이해하려는" 독자를 위해 위챗 공식계정 같은 공개 채널에 교과서 수준의 연재를 하고 싶을 때 써요.
- **사용 예:** `/deep-company-series 텐센트`
- **결과물:** `reports/{회사명}/《看懂{회사명}》/` 폴더에 편별 Markdown 파일(`0X-XX.md`)과 목차용 `00-系列说明.md`가 만들어지고, 사용자 검토·수정이 끝난 뒤에만 GitHub에 올라가요.
- **핵심 특징:** 회사 복잡도에 따라 편수를 조절하고, 편마다 정해진 뼈대를 따르며, '가짜 정밀성'을 걸러내는 7가지 팩트체크와 수정 요청 처리 절차가 핵심이에요.
:::

## 번역 전문

**원제:** XX 회사 이해하기(심층 기업 시리즈): 3-8편의 장문으로 한 회사를 해부하기

$ARGUMENTS 에 대해 《XX 이해하기》(역주: 원문 시리즈명은 `《看懂XX》`) 심층 장문 시리즈(3-8편, 회사 복잡도에 따라 결정 — '편수 조정' 참고)를 작성하여 위챗 공식계정/위챗 동영상 채널 등 공개 채널에 게시합니다. **핵심 IP는 '잘 쓰는 것'이 아니라 '잘 고치는 것'입니다 — 재테크·경제 기사의 99%가 이 skill의 팩트체크 기준을 위반하고 있습니다**.

참고 샘플: `reports/腾讯/《看懂腾讯》/`

## 1. 사용 상황

사용자가 한 회사에 대해 '교과서 수준'의 심층 연구를 하고, 이를 **장문 시리즈** 형태로 공개 게시하고 싶어 하는 경우입니다. 단일 리서치 리포트와의 차이는 다음과 같습니다.
- 3-8편(복잡한 회사는 8편 약 12만 자, 단순한 회사는 3편 약 3만 자)으로, 인지 리셋부터 의사결정 프레임워크까지 완전한 순환 구조를 이룹니다.
- 각 편은 독립적인 글로 완결되지만(단일 편 공유에 적합), 하나의 밸류에이션/경영진/가격 판단이 시리즈 전체를 관통합니다.
- '90분을 들여 한 회사를 이해하려는' 독자를 위해 쓰며, 증권사 고객을 위해 쓰는 글이 아닙니다.

**이 skill이 맞지 않는 상황**: 단일 리서치 리포트, 분기 실적 코멘트, 산업 리서치 — 이런 경우에는 `/investment-research`, `/earnings-review`, `/industry-research`를 사용합니다.

## 2. 시리즈 편 구성 템플릿

### 편수는 회사 복잡도에 맞춤(편수를 먼저 정하고, 그다음 편 구성을 정함)

**편수는 8편으로 고정되지 않습니다.** 8편은 텐센트처럼 '다수의 사업 + 조 단위 투자 포트폴리오 + 20년 경영진 이야기'를 가진 회사여야 감당할 수 있는 분량입니다. 쓰기 전에 먼저 묻습니다: 이 회사에는 '하나의 날카로운 질문'으로 독립된 글이 될 수 있는 주축이 몇 개 있는가? 있는 만큼 편수를 정합니다.

| 복잡도 | 특징 | 편수 | 예 |
|--------|------|------|------|
| 높음 | 여러 사업 부문이 각각 독립된 사업 + 숨은 자산/투자 포트폴리오 + 풍부한 경영진 관련 사료 | 7-8편 | 텐센트 |
| 중간 | 2-3개 사업 부문 + 하나의 중대한 시대 변수 | 4-6편 | — |
| 낮음 | 본업이 명확하고, 핵심 질문이 적고 집중되어 있음 | **3편** | 콰이서우 |

**3편 표준 통합 방식**(아래 8개 주축은 여전히 체크리스트이며 전부 다뤄야 하고, 다만 3편에 접어 넣을 뿐입니다):

| # | 편 제목 방향 | 접어 넣는 주축 |
|---|---------|-----------|
| 01 | 당신은 X를 이해했다고 생각한다(서두 + 사업과 해자) | 인지 리셋 + 해자 + 이익 엔진 개관 |
| 02 | X의 최대 변수(현재의 내러티브/숨은 자산) | 숨은 자산 + AI/시대 변수 |
| 03 | 얼마면 살 만하고, 어떤 신호면 반드시 팔아야 하나(재무 + 결정 최종편) | 재무 심층 + 경영진 요점 + 밸류에이션 결정 |

판단 신호: 어떤 편을 절반쯤 쓰다가 '분량 채우기'(같은 사실을 표현만 바꿔 반복)를 하고 있다는 걸 발견하면 편수를 너무 많이 잡은 것이므로 합칩니다. 반대로 어떤 편이 12,000자를 넘어도 다 담기지 않으면 나눕니다.

### 8개 주축 전체 템플릿(복잡한 회사에 사용, 단순한 회사는 체크리스트로 접어서 사용)

| # | 편 제목 템플릿 | 핵심 질문 | 글자 수 |
|---|---------|---------|------|
| 01 | 당신은 X를 이해했다고 생각하지만, 사실은 아니다 | 인지 리셋: 흔한 착각 3가지 깨기 | 4,000-5,000 |
| 02 | X의 해자 — `<사업 본질 한 문장>` | 해자는 깊은가, 향후 5/10년 뒤에도 남아 있는가 | 6,000-8,000 |
| 03 | X의 최대 이익 엔진 — `<가장 돈을 잘 버는 사업>` | 본업은 무엇이며, 왜 지속될 수 있는가 | 6,000-8,000 |
| 04 | X의 장부 속에 숨은 또 하나의 회사 — `<숨은 자산>` | 투자 포트폴리오 / 자회사 / 숨은 가치 | 8,000-10,000 |
| 05 | AI(또는 현재의 내러티브) 시대, X는 승자인가 패자인가 | 시대 변수: 사업별로 AI 영향을 분해 | 8,000-10,000 |
| 06 | 버핏의 방식으로 X의 실적 보고서를 해부하기 | 재무 심층: 매출총이익률/FCF/ROE/SBC | 8,000-10,000 |
| 07 | `<경영진 명언>` — X의 경영진은 믿고 맡길 만한가 | 자본 배분 규율 + 신뢰성 검증 + 후계자 | 8,000-10,000 |
| 08 | 얼마면 살 만하고, 어떤 신호면 반드시 팔아야 하나(시리즈 최종편) | DCF 3가지 시나리오 + 레드라인 목록 + 비중 프레임워크 | 10,000-12,000 |

`00-系列说明.md`(역주: '시리즈 안내') 한 편을 추가해 목차 색인으로 쓰며, 이 편은 게시하지 않습니다.

**편 구성은 반드시 회사에 맞춰야 합니다**: 이 템플릿은 텐센트에서 자라난 것이지 틀에 끼워 맞추는 도구가 아닙니다. 어떤 편에 독립된 내용이 없다면(예: 투자 포트폴리오가 없는 회사는 04편을 쓸 수 없음) 그 회사 고유의 주축(예: 콰이서우의 클링(Kling) AI, 전자상거래)으로 대체하거나, 위의 통합 방식에 따라 더 적은 편수로 접어 넣습니다. 판단 기준: 이 편이 '하나의 날카로운 질문'으로 독립된 글이 될 수 있는가.

## 2.5 편 내부 구조 템플릿(《텐센트 이해하기》 8편 본문에서 추출)

각 편은 자유롭게 쓰는 것이 아니라 고정된 뼈대가 있습니다. 공통 구조는 다음과 같습니다.

- **머리 인용 블록**: `> 《X 이해하기》 시리즈 · 제0N편 · <주축>`, 서두에 읽는 시간을 덧붙입니다.
- **첫 절은 언제나 훅(hook)**: 상식을 뒤집는 숫자 묶음 / 이례적인 곡선 하나 / 시장을 걱정시키는 숫자 하나로 시작하며, 배경 설명으로 뜸 들이지 않습니다.
- **각 편 끝**: `## 이번 편 요점 정리`(5-8개 항목, 숫자는 본문과 엄격히 일치) + `## 다음 편 예고`(날카로운 질문으로 예고하되 결론은 미리 밝히지 않음)
- **마지막 두 줄은 이탤릭**: `*이 글은 《X 이해하기》 시리즈 제0N편입니다...*` + `*이 시리즈는 공개 정보와 가치투자 프레임워크에 기반한 연구이며, 어떠한 투자 권유도 아닙니다.*`

편별 전용 뼈대:

| 편 | 뼈대 |
|---|------|
| 01 서두 | 주가가 시장에 의해 반복적으로 '재정의'된 역사적 곡선 → 흔한 착각 세 가지(각각 실적 보고서 데이터로 깨기) → '동시에 몇 개의 안경을 써야 하는가' 읽기 지도 표(02-08편으로 연결) → 밸류에이션 훅 숫자 표(여운만 남기고 결론은 주지 않음) |
| 02 해자 | 실패한 도전자 명단(실명·연도 포함) → 전환 비용의 본질(사용자가 무엇을 옮겨 갈 수 없는가) → 생태계 플라이휠 → 5년/10년 뒤에도 해자가 남아 있는가 → 역발상 사고 실험("내게 1000억이 있다면 이것을 복제할 수 있을까") |
| 03 이익 엔진 | 상식을 뒤집는 숫자로 시작 → 핵심 제품이 왜 오래가는가(가격 결정력 수준까지 분해) → 성장 여력 정량화(점유율 경로 + 반론: 이야기가 통하지 않을 가능성) → 조직 역량(왜 계속 제품을 만들어 낼 수 있는가) → 시장은 왜 저평가하는가 → AI/시대 변수가 이 사업에 미치는 영향 → 5년 뒤 그림 |
| 04 숨은 자산 | TOP 보유 지분 표(**연결 대상이 아닌 부분만 집계**, 연결 대상은 이중 계산 방지를 위해 별도 설명) → 회계 처리 차이(무엇이 손익계산서에 들어가고 무엇이 안 들어가는가) → '팔지 않을 것 vs 매각 가능성 있음' 분류 → 시장은 왜 할인하는가(항목별) → 몇 가지 뜻밖의 발견 → 할인율을 추정하는 간단한 방법 |
| 05 AI/시대 변수 | 시장을 걱정시키는 숫자 → 사업별로 승자/패자 분해(심하게 갈리므로 전체 결론은 내지 않음) → 핵심 반문("X가 단일 전선의 싸움에서 졌다면, 그래도 이길 수 있는가") → 5-10년 내 우회당하는 시나리오 추론(항목별로 반박하거나 인정) → 5가지 시나리오 → 향후 1년 모니터링 신호 목록 |
| 06 재무 | 이례적인 곡선 하나로 시작 → 손익계산서(매출총이익률 변화 요인 분석) → 기준 선택(Non-IFRS vs GAAP, 그 이유) → EPS와 자사주 매입 → 재무상태표(순현금) → 현금흐름과 FCF Yield → 주주환원을 '1달러 테스트'로 평가 → ROE 변화는 좋은가 나쁜가 → 밸류에이션 동종 비교 + 역사적 비교 → 가치투자 10개 항목 Checklist 하나씩 점검 → 실적 보고서를 세 문장으로 압축 |
| 07 경영진 | 핵심 팀 표 → 핵심 인물의 장기적 기여(형용사가 아닌 구체적 결정으로) → 이해관계 일치(지분/보수가 이익에서 차지하는 비율) → **신뢰성 검증: 실제 위기 하나를 골라 대응을 본다** → 5년 약속 이행률(당시 발언을 항목별로 대조) → 자본 배분 규율 → 후계 구도 우려(회피하지 않음) → '사람을 사는 세 가지 질문'(정직한가/유능한가/일을 사랑하는가) → 종합 점수 |
| 08 결정 | SOTP 부문별 밸류에이션('당신이 사는 것이 정확히 무엇인지' 명확히) → 역사적 밸류에이션 분위 + **반드시 '백미러는 내비게이션이 아니다'라고 경고** → 미래 이익 3가지 시나리오 표(낙관/중립/보수 + 내재 성장률, '예측이지 사실이 아님'을 명시) → 레드라인 목록(발동 ≠ 반드시 매도, 그러나 반드시 재검토) → 확률·배당(odds) 사고로 마무리 |

## 3. 글쓰기 스타일 규범

### 어조

- **직설적이고 날카롭게, 군더더기 없이** — 첫 문장부터 숫자나 상식을 뒤집는 결론을 제시합니다.
- **가치투자 프레임워크** — 버핏/멍거/돤융핑/리루의 관점을 곳곳에 섞되, 명언을 늘어놓지는 않습니다.
- **입장을 미리 정하지 않음** — 먼저 데이터를 펼치고, 그다음 논리를 전개하고, 마지막에 결론을 냅니다.
- **양면을 제시** — 모든 핵심 판단에 '하지만 다른 한편으로는...'이라는 반대 관점을 붙입니다.
- **위챗 공식계정 감각** — 앞의 18-20자가 반드시 그 자체로 성립해야 합니다(모바일 미리보기).

### 금지어

| 금지 | 이유 | 대체 |
|------|------|------|
| 명백히 / 필연적으로 / 반드시 | 주관적 절대화 | 데이터에 따르면 / 증거가 보여 주듯 |
| 내 생각에는 / 나는 ~라고 본다 | 주관적 말투 | 삭제하거나 '이 프레임워크에 따르면'으로 변경 |
| 교과서 수준 / 신의 한 수 | 조회수용 찬사 | 구체적 사실을 서술 |
| 심각한 불일치 / 심각한 저평가 | 강한 주관어 | 구체적인 할인율(%)을 제시 |
| 완벽하다 / 흠잡을 데 없다 | 일방적 판단 | 반대 관점의 관찰을 추가 |

### 제목 스타일

- **대비되는 숫자**나 **통념을 뒤집는 결론**을 훅으로 씁니다("15년간 7번의 도전이 모두 실패", "연봉 4292만이 이익의 만분의 1.65에 불과").
- 부제는 중립적으로 내용을 요약합니다("— `<본질 판단>`").
- **조회수용 비유는 피합니다**: '리틀 버핏', '중국판 X', 'YYDS' 같은 표현은 일절 쓰지 않습니다.
- 전문 독자에게 익숙한 용어를 씁니다('버핏'보다 '버크셔', 인명보다 회사명 우선).

## 4. 엄격한 팩트체크 Checklist(핵심 IP)

### 쓰기 전부터 경계해야 할 '가짜 정밀성' 함정

1. **확률 가중 기대값**: `30% × A + 50% × B + 20% × C = 기대값 +X%` 같은 계산은 거의 전부 쓰레기입니다 — 확률 배분은 순전히 주관적이어서 독자에게 잘못된 정밀함을 줍니다. **시나리오 + 발동 조건 + 방향만 나열하고, 가중 기대값은 계산하지 않습니다**.
2. **제3자 추정 MAU/점유율**: QuestMobile/치마이(Qimai)/CBNData 등은 집계 기준 차이가 매우 큽니다(같은 시점에 2-3배 차이가 날 수 있음). **가장 신뢰할 만한 두 곳만 비교 기준점(anchor)으로 쓰고, 나머지는 정성적으로 서술합니다**.
3. **과거 성장률의 선형 외삽**: `2025년 +33% × 5년 복리 → 2030년 X`는 금융 문맹식 예측입니다. **시나리오 가정 + 높음/낮음 구간 + 약속이 아님을 명시합니다**.
4. **공개되지 않은 지분율**: 바이트댄스, Halti 같은 비상장사 지분은 **한 번도 공개된 적이 없습니다**. **구간으로 제시하고 '알 수 없음'으로 표시합니다**.
5. **강한 인과 귀속**: 경쟁사가 실패함 = X 때문. 여러 원인을 모두 나열하고, **이 글에서는 단일 원인으로 귀속하지 않습니다**.

### 수정 시 반드시 돌려야 할 7가지 점검

```
□ 1. 편 간 숫자 일관성: 시가총액, Non-IFRS 순이익, 핵심 지분 %를 시리즈 전체에서 일치시킬 것
□ 2. 기준 표기: Non-IFRS / GAAP / Non-IFRS-SBC / FCF 중 각각 무엇을 썼는지 전체 글에서 명확히 할 것
□ 3. 중복 합산 점검: 이미 연결된 자회사는 '투자 포트폴리오'에 넣지 않고, SOTP에서 이중 계산하지 않을 것
□ 4. 동종 비교의 공정성: '본업 PER(현금+포트폴리오 제외)' vs '경쟁사 PER(제외하지 않음)'처럼 비교하면 안 됨
□ 5. 확률 가중치 전부 삭제: 위 항목 참고
□ 6. 절대화 표현 전부 완화: grep "显然|必然|严重|教科书|完美"
□ 7. 제3자 데이터 출처 표기: 실적 보고서가 아닌 데이터마다 뒤에 "(출처: X)"를 붙일 것
```

(역주: 6번의 grep 대상은 중국어 금지어 '명백히|필연적으로|심각하게|교과서|완벽'입니다.)

### 모델 편향

쓰기 전에 **이미 알려진 명백한 오류 위험을 먼저 나열합니다**:
- 과거 수익 배수: 반드시 누적 투입액 기준을 사용합니다(예: Riot은 58배가 아니라 33배).
- 지분율: 반드시 최신 푸투(Futu)/실적 보고서 기준을 확인합니다(예: 텐센트의 메이퇀 지분은 6.4%가 아니라 1.5%).
- '현물 배당(분배)' 회계 처리: 처분 이익으로 간주해 IFRIC 17에 따라 선언일에 인식합니다(예: 징둥은 2021년, 메이퇀은 2022년이지만 금액은 작음).
- 총 발행주식 수는 반등할 수 있습니다: SBC를 연초에 집중 부여하면 주식 수가 단기적으로 늘어납니다.

## 5. 실행 절차

### 1단계: 조사(01-02편을 쓰기 전에 완료)

1. 회사의 최근 5년 연차보고서와 최신 분기 보고서를 읽습니다.
2. 독립적인 셀사이드(증권사) 리포트를 최소 3편 읽습니다(컨센서스 + 역컨센서스 찾기).
3. `/investment-team` 또는 `/investment-research`로 먼저 내부 연구 초안을 생성합니다.
4. 사용자와 8편의 핵심 논지를 확인합니다(다 쓰고 나서야 방향이 틀렸음을 발견하는 일을 피하기 위함).

### 2단계: 집필(01 → 마지막 편 순서대로 쓰며, 건너뛰지 않음)

- 각 편을 다 쓰면 먼저 `reports/{회사명}/《看懂{회사명}》/0X-XX.md`에 저장합니다.
- **디렉터리 충돌 규칙**: `reports/{회사명}/《看懂{회사명}》/`가 이미 존재하면(구버전 시리즈) 덮어쓰거나 섞어 두지 않습니다 — 새 시리즈는 날짜 접미사가 붙은 새 폴더 `reports/{회사명}/《看懂{회사명}》-{YYYYMMDD}/`에 쓰고, 기존 폴더는 그대로 보존합니다.
- 곧바로 GitHub에 push하지 않습니다 — 사용자 검토를 기다립니다.
- 사용자가 수정 의견을 주면 수정합니다.
- 수정이 끝난 뒤에야 git push합니다.

### 3단계: 편 간 일관성 스캔(모든 편을 다 쓴 뒤)

Explore agent를 보내 시리즈 전체를 병렬로 스캔하며 다음을 점검합니다.
1. 같은 숫자(시가총액, 순이익, 지분율)가 편마다 일치하는가
2. 같은 용어(FBS, SBC, Non-IFRS)가 처음 등장할 때 설명되었는가
3. 참조 관계: 02편에서 '06편 참고'라고 했다면 실제로 대응되는가
4. 요점 정리와 본문의 숫자가 일치하는가

### 4단계: 게시 전 최종 점검

```bash
# push 전에 반드시 로컬에서 grep을 한 번 실행(ai-berkshire 개인정보 규칙에 따름)
grep -r "<로컬 사용자명>\|/Users/\|<개인 식별 정보>" reports/ | head
```

이상이 없음을 확인한 뒤에야 `git pull --rebase && git commit && git push`를 실행합니다.

## 6. 수정 의견 처리 절차

사용자가 수정 의견을 주면 다음 순서로 처리합니다.

### 1. 먼저 사실을 확인(바로 고치지 말 것)

사용자가 "X 데이터가 틀렸다"고 하면, 먼저 Bash/Read로 원자료를 찾아 교차 검증합니다.
- ai-berkshire 프로젝트 안의 같은 회사 earnings/실적 보고서 리포트를 확인합니다.
- 푸투/공식 공시를 확인합니다.
- '사용자가 말한 데이터 vs 내가 찾은 데이터 vs 내가 이전에 쓴 데이터'의 3자 비교를 제시합니다.

### 2. 수정 등급 판단

| 등급 | 유형 | 처리 |
|------|------|------|
| 🔥 명백한 오류 | 숫자 오류, 인과 귀속 오류, 기준 오류 | 반드시 수정, 망설일 필요 없음 |
| ⚠️ 주관화 | 강한 주관어, 절대화, 조회수용 비유 | 완화하거나 삭제 |
| 🔬 세분화 | 출처 표기, 기준 세분화 | 우선순위 낮음, 가독성과 균형을 맞춰 처리 |
| ❓ 신뢰 불가 | 제3자 추정치 간 차이가 큼 | **고치는 것보다 삭제가 더 안전**(사용자의 명시적 지시) |

### 3. 수정 후 연동 점검

한 곳을 고치면 먼저 '어느 곳에서 이 숫자/개념을 또 인용하는가'를 생각합니다. 예:
- 시가총액을 고침 → 시리즈 전체의 PER / 본업 PER / 할인율 / FCF Yield를 연동 수정
- 지분 %를 고침 → TOP 10 순위 + 과거 지분 표 + 지분 매각 목록을 수정
- 용어 기준을 고침 → 최초 정의 + 이후 인용 + 요점 정리를 수정

### 4. push 후 즉시 보고

```
push 성공(commit hash).
[N]곳 수정 요약 [표 포함]:
- 무엇을 고쳤는지
- 연동해서 무엇을 고쳤는지
- 아직 고치지 않은 것은 무엇인지

다음 지시를 기다립니다.
```

## 7. 이 skill이 하지 않는 것

- **독자 대신 투자 결정을 내리지 않습니다** — 모든 편 끝에 '투자 권유가 아님'을 명시합니다.
- **주가를 예측하지 않습니다** — '시나리오 + 발동 조건'만 제시합니다.
- **'기대 연환산 수익률' 가중값을 계산하지 않습니다** — 주관적 확률 배분은 독자를 오도합니다.
- **'X 거물도 보유하고 있다'고 쓰지 않습니다** — 남의 보유 종목으로 자신의 판단을 보증하는 것은 가치투자에 반합니다.
- **8편을 억지로 다 쓰지 않습니다** — 어떤 편에 독립된 내용이 충분하지 않으면(예: 어떤 회사의 경영진이 특별히 다룰 만하지 않음) 다른 편에 합치거나 편수를 줄입니다.

- 모든 공개 보고서는 **공개 정보만 사용합니다**(실적 보고서, 공식 공시, 증권사 리포트, 저명한 제3자 기관).

- 공개 서명은 사용자의 다층 신원 전략에 따르며, 섞어 쓰지 않습니다.
